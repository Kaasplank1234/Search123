# Security Policy

Search123 takes security seriously. If you discover a security vulnerability, please follow the responsible disclosure process outlined below.

## Reporting Security Vulnerabilities

If you discover a security vulnerability in Search123, please **do not** create a public GitHub issue. Instead, please report it privately through the following channels:

### Contact Cheesy Studios

Please contact Cheesy Studios directly through their contact page:

**Contact Page:** [https://www.cheesy-studios.22web.org/neem-contact-met-ons-op-faq](https://www.cheesy-studios.22web.org/neem-contact-met-ons-op-faq)

When reporting a vulnerability, please include:

1. A clear description of the vulnerability
2. Steps to reproduce the issue (if applicable)
3. Potential impact or severity
4. Any suggested fixes or mitigation steps (if you have them)
5. Your contact information for follow-up communication

## Responsible Disclosure

We ask that security researchers:

- **Do not publicly disclose** the vulnerability details until we have had time to investigate and address it
- Allow a reasonable timeframe (typically 90 days) for us to develop and deploy a fix
- Provide regular updates if the timeline needs adjustment
- Avoid accessing or modifying user data, services, or systems beyond what is necessary to demonstrate the vulnerability

## Security Updates

Once a security issue is confirmed and fixed, we will:

1. Release a patched version as soon as possible
2. Credit the reporter (unless they request anonymity)
3. Publish details about the vulnerability in a responsible manner

## Additional Security Information

For general security-related questions or concerns about Search123's deployment and operational security, please also contact Cheesy Studios through their contact page.
